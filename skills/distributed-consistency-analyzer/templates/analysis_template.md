## 8. 重要警告とポイント

### 🚨 絶対に忘れるべきでない点

1. **完全性への幻想**
   - どちらの順序でも完全な安全性はない
   - 不整合発生のリスクは常に存在

2. **定期的な監視が必須**
   - 孤立ファイル・孤立レコード検出スクリプト
   - エラーログの定期確認

3. **修正後の再評価**
   - 実装後に必ず検証
   - 新たな問題の有無確認
   - ドキュメント更新

4. **組織のリスク許容度に応じたカスタマイズ**
   - セキュリティ優先 ← → UX優先
   - 完全性重視 ← → 検出容易性重視
